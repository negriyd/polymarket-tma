Z. Миграция на Polymarket CLOB v2  [PARTIAL — 2026-05-23]
  • Polymarket с 22 апреля 2026 переключили CTF Exchange на новую схему ордеров.
    Старый v1-контракт (0x4bFb41d5B3570DeFd03C39a9A4D8dE6Bd8B8982E) с 30 апреля
    отдаёт 400 "order_version_mismatch" — все интеграторы 0.34.6-стека сломаны.
  • [DONE] Поменяли OrderBuilder под v2 EIP-712 (domain version="2"; struct: salt,
    maker, signer, tokenId, makerAmount, takerAmount, side, signatureType, timestamp,
    metadata, builder — без nonce/feeRateBps/taker).
  • [DONE] ClobOrderClient → новый JSON envelope: owner = API key UUID,
    deferExec/postOnly на верхнем уровне, signature внутри order, salt/signatureType
    — JSON number.
  • [DONE] application.yml: ctf-exchange-address (v2) = 0xE111180000…E1f4F00237545B87B996B,
    neg-risk-ctf-exchange-address (v2) = 0xe2222d279d744050d28e00520010520000310F59.
  • [DONE] Регрессионные тесты: OrderBuilderTest и ClobOrderClientPayloadTest
    (включая mapping CLOB_ORDER_VERSION_MISMATCH и CLOB_DEPOSIT_WALLET_REQUIRED).
  • [BLOCKED — UPSTREAM] Polymarket CLOB v2 фактически отключил прямую торговлю
    с EOA. На корректно собранный v2-ордер сервер отвечает 400 "maker address not
    allowed, please use the deposit wallet flow". Чтобы торговать через API,
    кошелёк должен сначала пройти онбординг на polymarket.com (депозит + одна
    маленькая сделка) — это деплоит CREATE2-прокси deposit wallet, после чего
    ордера должны идти с signatureType=3 (POLY_1271, ERC-7739-обёртка),
    maker=proxy, signer=EOA. На середину мая 2026 у Polymarket этот путь до сих
    пор сломан (issues #51, #53, #61, #63, #64 в py-clob-client-v2). Ждём фикса
    апстрима. Пока бэкенд маппит 400 в CLOB_DEPOSIT_WALLET_REQUIRED, фронт
    показывает понятный тост.
