Шаги, чтобы добить сквозной сценарий для пользователя (RU)
A. Ставки (ордера)
  1. Исправить typedData до формата, который принимают Privy/viem и CLOB (все нужные числа — согласованно, домен включая chainId).
  2. Реализовать настоящий orderHash (EIP-712 digest совпадает с ожиданием CLOB).
  3. L1 + L2 по документации CLOB для каждого запроса POST /order (как у вас в TODO).
  4. Ончейн approvals перед первым ордером (USDC + conditional tokens для exchange).
  5. Выбор правильного signatureType и связки maker/signer под ваш тип кошелька (EOA vs proxy).

B. Текущие ставки / позиции
  1. Полировать GET /api/positions + UI: суммы, средняя цена, рынок, outcome (YES/NO), при желании связка с локальными favorite.
  2. При необходимости — второй источник (Gamma/market slug) только для человекочитаемого заголовка.

C. Уведомления «рынок зарезолвился / можно redeem»
Варианты (на выбор уровень сложности):
  • Polling Data API позиций + поля «resolved / redeemable / claimable» если API их отдаёт.
  • Лёгкая оффчейн job по спискам conditionId ваших активных пользователей — запрос статусов рынков в Gamma.
  • Тяжёлое: подписка на логи ончейн Resolution / индексатор Polymarket.

Дальше: Firebase / Telegram Bot API отправка сообщения пользователю (у вас уже есть Telegram — логически связать Telegram user id ←→ уведомления).
D. Получение выигрыша (redeem)
  1. Спека вызова Conditional Tokens Framework для redeemPositions / аналога по актуальной сети контрактов Polymarket.
  2. Бэкенд отдаёт unsigned tx calldata + to + value, фронт подписывает и отправляет через Privy (или делать meta-tx только если поддерживается).
  3. Отдельный экран «Claim» по позиции с суммой USDC после успешной транзы.

Если нужно, следующим шагом могу конкретно предложить патч под OrderBuilder (единый строковый формат uint полей для Privy), это часто первый быстрый способ проверить гипотезу про ошибку подписи.
